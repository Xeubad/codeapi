# 上游借鉴来源记录

> **2026-10-31 角色变更**：本文件从「逐提交决策台账」改为「**借鉴来源记录**」。
> 本 fork 已完全脱离上游节奏（见 `AGENTS.md` 与 [FORK_MAINTENANCE_CN.md](./FORK_MAINTENANCE_CN.md)），
> 不再要求评估每一个上游提交，也不再记录拒绝项与「已评估到哪个 tag」。
> 这里只记**实际拿进来的东西**：来源、落地方式、改动文件、与上游的差异。
> 下方 2026-10-29 的逐提交条目与模板保留作历史审计，不再按它执行。

上游镜像由 `upstream/main` 远端引用承担，只是只读参考，不是基线也不是待办来源。`main` 不与它保持祖先关系，且永不 `git merge upstream/main`。

## 借鉴条目模板（新）

每次借鉴落地后新增一节，新条目插在最上面。

```markdown
### <功能名>（借鉴自上游 v0.2.XX）

- 借鉴日期：YYYY-MM-DD
- 上游来源：<short-sha> <subject>（可多个；若为重写实现，写「参考自」而非提交清单）
- 落地方式：cherry-pick -x ／ 按本 fork 设计重写 ／ 部分搬运
- 改动文件：…
- 与上游的差异：…（哪些地方故意不同，为什么）
- 验证：…（跑了什么，结果）
- 回滚点：<短 SHA> 或 revert 说明
```

## 安全类内容的处理方式

上游的鉴权、密钥、SSRF、注入、越权、计费一致性修复**不再默认必采**，但每次「看一眼上游」时仍单独标 🔴 并写清不采纳的风险，由用户决定。本 fork 自身不得删除、绕过或弱化平台已有的校验与审计逻辑——这条与是否跟随上游无关。

| 车道 | 范围 | 默认动作 |
