# 上游更新决策台账

本台账是「解耦 + 选择性 cherry-pick」模式（2026-10-29 起）的核心记录。每个评估过的上游提交都必须在这里留痕：采纳、拒绝还是延后，为什么。没有记录的决策等于没做过。

上游镜像由 `upstream/main` 远端引用承担，`main` 不与它保持祖先关系。执行规则见根目录 `AGENTS.md`。

## 决策车道

| 车道 | 范围 | 默认动作 |
|---|---|---|
| 🔴 安全 | 鉴权、密钥处理、SSRF、注入、越权等修复 | 必须采纳；拒绝必须写风险评估与后果声明 |
| 🟠 协议/Provider | OAuth、流式、模型列表、计费一致性等修复 | 按本 fork 实际使用的 Provider 决定 |
| 🟡 新功能 | 上游新特性 | 按产品方向与二开范围决定 |
| ⚪ 其他 | CI、文档、重构、上游版本号 chore | 默认拒绝 |

决策标记：✅ 采纳（记落地短 SHA）／ ⏭️ 拒绝（记理由）／ ⏸️ 延后（记复评条件）。

## Release 条目模板

每个评估过的上游 release 复制以下模板新增一节，新条目插在最上面。

```markdown
### v0.2.XX（上游）

- 评估日期：YYYY-MM-DD
- 范围：`v0.2.XX-1..v0.2.XX`，N 个提交；上游头 SHA：`<full-sha>`
- 评估基线：`origin/main` = `<short-sha>`
- 决策统计：采纳 X ／ 拒绝 Y ／ 延后 Z
- 🔴 安全修复清单与去向：<无则写「本批次无安全修复」>
- ⏭️ 拒绝项后果声明：<拒绝了哪些修复，不采纳的风险是什么>

| 上游提交 | 类型 | 决策 | 理由 | 落地 SHA / 台账号 | 备注 |
|---|---|---|---|---|---|
| <short-sha> <subject> | 🔴/🟠/🟡/⚪ | ✅/⏭️/⏸️ | … | UP-YYYY-NNNN | … |
```

台账号规则：`UP-<年份>-<四位序号>`，全年递增，用于工作日志和提交信息互相引用。
